# Report a bug

## Open a GitHub report

1. Open **Report a Bug** from the main menu or an active duty.
2. Describe the problem and choose **Report on GitHub**. The game prepares a ZIP and opens a draft with the version, position and problem description filled in.
3. Drag the prepared ZIP into GitHub's **Diagnostic ZIP or screenshots** field, or use **Show in Finder** to locate it. Review the public issue and submit it in GitHub.

Use **Export ZIP** to save a local copy. The archive contains the description, app and macOS versions, and the available game diagnostics from the last ten minutes. It excludes account keys and save files. Long descriptions are included in full inside the ZIP.

## Include enough information to reproduce it

- **Version/build:** for example, v1.0.14 / build 48.
- **Airport and position:** for example, RCTP / GND.
- **Traffic:** endless rate/level or the relevant fictional CSV rows.
- **Weather and speed:** including simulation multiplier and whether it was paused.
- **Steps:** a short numbered list of actions.
- **Expected result / actual result.**
- **Screenshot:** keep the affected area, selected aircraft/tag and useful controls visible. Exclude the desktop and personal information.
- **Diagnostics:** the reviewed ZIP, if available.

For ground line problems, include the taxiway/stand identifier, zoom and an overview as well as the close-up. For ILS problems, include runway, procedure, actual/cleared altitude, IAS, LOC/GS status and the last radio messages. For performance problems, distinguish loading, typing, dragging and zooming, and describe how long the slowdown lasts.
